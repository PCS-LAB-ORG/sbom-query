# sbom-query

Lightweight Python CLI tool to query CycloneDX JSON SBOMs for specific packages and version ranges, with Linux distro version normalization and CSV
reporting.

---

## Overview & How It Works

`sbom-query` scans directories of CycloneDX JSON Software Bill of Materials (SBOM) exports—such as container and application archives generated by
Prisma Cloud, Cortex Cloud, Trivy, or Syft—to locate specific libraries, binaries, or version ranges across your environment.

Under the hood, the tool executes four steps:

1. **Recursive CycloneDX Discovery:** Walks the target directory (`-d`) recursively for `.json` files and inspects the root metadata for
   `"bomFormat": "CycloneDX"`, automatically skipping unrelated JSON files (such as `package.json` or `config.json`).
2. **Case-Insensitive Rule Parsing:** Loads target rules from a file (`-l`), inline CLI flags (`-p`), or both. Package names are normalized to
   lowercase during lookup so `PyYAML` matches `pyyaml`, while preserving original casing in output reports.
3. **Linux Distro Version Normalization:** Container packages frequently include package manager epochs and OS build suffixes (for example, `2:8.2.7`
   or `8.3.6-0ubuntu0.24.04.12+deb12u1`). Before evaluating PEP 440 semantic version constraints, `sbom-query` strips epochs and distribution metadata
   to extract the clean upstream version (`8.2.7` or `8.3.6`).
4. **Console & CSV Reporting:** Prints matching components to `stdout` and exports a timestamped CSV report enriched with container image metadata,
   Package URLs (PURLs), licenses, and relative file paths.

## Installation

1. **Clone the repository:**
   ```bash
   git clone https://github.com/PCS-LAB-ORG/sbom-query.git
   cd sbom-query
   ```

2. **(Optional) Create and activate a virtual environment:**
   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   ```

3. **Install dependencies:**
   `sbom-query` uses Python 3 standard libraries for CLI parsing, JSON, and CSV handling, requiring only the `packaging` library:
   ```bash
   pip install -r requirements.txt
   ```

4. **Set up your local target list:**
   Copy the sample rule file to create your own working list:
   ```bash
   cp packages.example.txt packages.txt
   ```

## Quick Start & Examples

Every run requires **`-d` / `--directory`** and at least one query source (**`-l` / `--list`** or **`-p` / `--package`**).

```bash
# 1. Query SBOMs using a rule file
python3 sbom_query.py -d ./sbom_exports -l packages.txt

# 2. Run a quick inline query without creating a rule file (-p is repeatable)
python3 sbom_query.py -d ./sbom_exports -p "openssl@<3.0.13" -p "curl"

# 3. Combine a baseline rule file with an extra inline package check
python3 sbom_query.py -d ./sbom_exports -l packages.txt -p "php8.3-fpm@<8.3.36"

# 4. Write results to a custom CSV path
python3 sbom_query.py -d ./sbom_exports -l packages.txt -o audit_report.csv

# 5. Print results in the terminal only (skip CSV generation)
python3 sbom_query.py -d ./sbom_exports -p "@babel/helper-hoist-variables@7.22.5" --no-csv

# 6. Use as a CI/CD policy gate (exits with status code 1 if any match is found)
python3 sbom_query.py -d ./sbom_exports -l packages.txt --quiet --fail-on-match
```

## CLI Options

| Flag                |   Required   | Description                                                                                      |
|:--------------------|:------------:|:-------------------------------------------------------------------------------------------------|
| `-d`, `--directory` |     Yes      | Root directory to scan recursively for CycloneDX JSON SBOM files.                                |
| `-l`, `--list`      | Conditional* | Path to a text file containing target packages and version rules.                                |
| `-p`, `--package`   | Conditional* | Inline target package rule (e.g., `'curl'` or `'php8.3@<8.3.36'`). Can be passed multiple times. |
| `-o`, `--output`    |      No      | Custom output CSV path (default: `sbom_query_results_YYYYMMDD_HHMMSS.csv`).                      |
| `--no-csv`          |      No      | Print matching components to stdout without writing a CSV file.                                  |
| `-q`, `--quiet`     |      No      | Suppress summary banners and progress messages (outputs only matches and errors).                |
| `--fail-on-match`   |      No      | Exit with code `1` if one or more matching components are found.                                 |
| `-h`, `--help`      |      No      | Display help message and usage examples.                                                         |
| `-v`, `--version`   |      No      | Print the `sbom-query` version number and exit.                                                  |

*\*At least one of `-l` or `-p` must be provided.*

## Query Rule Syntax

Rules follow the exact same `package[@constraint]` syntax whether loaded from `-l` or passed inline via `-p`. In rule files, blank lines and lines
starting with `#` are ignored.

### 1. Catch-All (Match Any Version)

Omit `@` to flag every installed version of a package or binary:

```text
php8.1
telnet
curl
```

### 2. Exact Version & Discrete Version Lists

Specify a single version, or separate multiple discrete versions with commas (`OR` logic):

```text
angulartics2@14.1.2
xz-utils@5.6.0, 5.6.1
```

### 3. Comparison Operators & Compound Ranges

Supports PEP 440 operators (`<`, `<=`, `>`, `>=`, `==`, `!=`). When all comma-separated clauses begin with an operator, they are evaluated as a
compound **`AND`** range:

```text
# Strictly below 3.0.13
openssl@<3.0.13

# Greater than or equal to 8.3.0 AND strictly below 8.3.36
php8.3@>=8.3.0,<8.3.36
```

### 4. Inclusive Hyphen Range Shorthand

Hyphen ranges automatically expand to `>=MIN,<=MAX`:

```text
log4j-core@2.0.0 - 2.14.1
```

### 5. Scoped Packages (npm, etc.)

Scoped package names starting with `@` (such as `@babel/helper-hoist-variables` or `@nestjs/core`) split on the final `@` delimiter:

```text
@babel/helper-hoist-variables@7.22.5
@nestjs/core@<10.0.0
```

> **Tip for Linux Container SBOMs:** Debian and Ubuntu packages often embed the minor version directly into the package name (e.g., `php8.3`,
> `php8.3-fpm`) alongside standalone binary detections (`php`). Include both the base binary name and distro package names in your rule list for
> complete coverage.

## Output & Exit Codes

### CSV Report Columns

When matches are found and `--no-csv` is not set, results are written to `sbom_query_results_YYYYMMDD_HHMMSS.csv`:

| Column             | Source in CycloneDX JSON     | Description                                                         |
|:-------------------|:-----------------------------|:--------------------------------------------------------------------|
| **Image Hash**     | `metadata.component.name`    | Scanned container image name or digest.                             |
| **Image Version**  | `metadata.component.version` | Container image tag or version string.                              |
| **Component Type** | `metadata.component.type`    | Top-level scanned artifact type (e.g., `container`, `application`). |
| **Package**        | `components[].name`          | Matched component name as recorded in the SBOM.                     |
| **Version**        | `components[].version`       | Raw component version string from the SBOM.                         |
| **PURL**           | `components[].purl`          | Package URL (e.g., `pkg:deb/ubuntu/php8.3@...`), or `N/A`.          |
| **SBOM File**      | File path                    | Relative path to the matching SBOM JSON file from `--directory`.    |
| **Author**         | `components[].author`        | Package author or maintainer metadata, or `N/A`.                    |
| **Licenses**       | `components[].licenses`      | JSON-serialized license array, or `N/A`.                            |

### Exit Codes

| Code | Meaning                                                                                              |
|:----:|:-----------------------------------------------------------------------------------------------------|
| `0`  | Scan completed successfully (no matches found, or matches found without `--fail-on-match`).          |
| `1`  | Invalid CLI arguments/paths, missing rule file, or matches found while `--fail-on-match` is enabled. |
